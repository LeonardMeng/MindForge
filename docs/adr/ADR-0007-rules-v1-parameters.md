# ADR-0007 规则 v1 的聚合参数：按维度的参考时间、双曲衰减、只用精确运算

- **状态**：已定（**参数暂定**：M5 检查点后根据实际使用复审；状态机的阈值在 2.4 补进本 ADR）
- **日期**：2026-11-20

## 背景

掌握度投影 = fold(证据, 规则@版本)，必须逐字节确定（不变量 3），merge driver 在别的设备上重算也要得到同样的字节（ADR-0006）。ROADMAP 2.3 要求按时间衰减加权、按评测类型加权、`null` 不参与平均、置信度随证据数量和一致性变化。

## 决策

每个维度只看给它打了分的证据（`null` 不参与；没有这样的证据时，维度是 `null`）。参数集中在 `rules-v1` 的 `V1_PARAMETERS`。

- **参考时间**：证据的年龄从**这个维度**最新的证据的 `created_at` 算起，不是全部证据里最新的，也不是 `clock.now()`。
- **时间衰减**：`H / (H + ageDays)`，`H = 30`：比最新的证据早 30 天的证据权重减半，90 天时是四分之一。
- **评测类型权重**：独立验证 1.0，练习 0.6，自评 0.3。
- **分数**：权重 = 衰减 × 类型权重，分数是加权平均。
- **维度置信度** = 数量 × 一致性：
  - 数量 `C / (C + 1)`，`C` = Σ 权重 × 证据自己的 `confidence`。证据的 `confidence` 只影响置信度，不影响分数。
  - 一致性 `1 − 2 × 加权平均绝对偏差`（分数在 0..1 里，偏差不超过 0.5）。
- **总置信度**：有分数的维度的置信度的平均；没有证据时为 0。
- **criteria 版本**：所有版本的证据一起聚合；对版本的要求属于状态机（2.4）。
- **输出**：先按证据 id 排序再求和；每个数四舍五入到 4 位小数，`-0` 写成 0。

## 理由

- **按维度的参考时间**：用 `now` 时，没有新证据投影也会每天变化，违反不变量 3，merge driver 也没法重算。用全部证据里最新的时间，只测了 recall 的一条新证据会让其他维度的证据“变旧”、置信度下降。按维度算，加一条不给某维度打分的证据，不会改变那个维度（有属性测试）。按真实日期过期是复习调度的事（2.7：到期的 `mastered` 转为 `needs_review`）。
- **只用加减乘除和绝对值**：ECMAScript 规范里 `Math.exp`、`Math.pow`、`Math.sqrt` 等的结果是近似的，不同引擎或 Node 版本可能差最后一位，投影就不再逐字节相同。IEEE 754 的加减乘除结果唯一。所以衰减用双曲函数而不是指数，一致性用平均绝对偏差而不是标准差。
- **排序后求和**：浮点加法不满足结合律，读文件的顺序不能影响结果。
- **4 位小数**：YAML 易读、稳定；4 位已经比评分本身的精度高。
- **证据的 `confidence` 不进分数权重**：否则一个维度的证据 `confidence` 全是 0 时，分数没有定义。

## 考虑过的其他方案

- **从 `clock.now()` 算年龄**：投影随日期变化，见上。
- **从全部证据里最新的时间算年龄**：维度之间互相影响，见上。
- **指数衰减 `2^(−age/H)`、标准差**：需要 `pow`、`sqrt`，跨平台不保证逐位相同。
- **不舍入**：任何一点运算差异都会改变文件字节，YAML 也难读。

## 后果

- 改任何参数都要发布新的规则版本（`rules_version`），旧投影按旧版本可以复现；M5 检查点后复审时也是这样。
- 规则代码不能用近似的数学函数；新增参数先写进本 ADR。
- 舍入边界附近，排序是唯一保证结果不受读取顺序影响的手段；排序不能去掉。
