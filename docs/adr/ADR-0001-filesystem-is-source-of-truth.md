# ADR-0001 文件系统是权威数据源，SQLite 只是可重建的索引

- **状态**：已定
- **日期**：2026-11-19（决策日期早于仓库创建，2026-11-20 补记）

## 背景

Mastery OS 要求本地优先、用户拥有自己的数据，并用 Git 管理历史和同步（README 第 1 节）。同时，查询、全文搜索和 wikilink 解析需要一个能快速检索的结构。

## 决策

- 用户数据都是普通文件（Markdown / YAML / JSON），文件系统是唯一的权威数据源。
- SQLite（含 FTS5）只是索引，放在 `.mastery/` 里，不提交，随时可以删除、可以重建。

## 理由

- 用户不打开应用也能读懂自己的数据。
- 文本文件可以用 Git 做 diff 和合并；SQLite 是二进制文件，Git 合并不了，没法同步。
- 每台设备的索引可以不一样，比如手机上只保留一部分。
- 索引的 schema 版本不对时直接重建，永远不用写数据库迁移。

## 考虑过的其他方案

- **以 SQLite 为权威，再导出成文件**：没法合并，也不好迁移到别的工具。
- **同步 SQLite 文件**：二进制文件会冲突，而且和文件重复存了同样的信息。
- **CRDT 数据库**：起步阶段太复杂。

## 后果

- 所有写入都先落到文件，再增量更新索引（README 第 4 节“写入路径”）。
- 删除 `.mastery/` 不能丢数据，`mastery reindex` 之后查询结果必须和删除前一致（不变量 1）。
- 写文件必须是原子写（不变量 6）。
