# ADR-0013 文件格式约定：同一个值只有一种写法

- **状态**：已定
- **日期**：2026-11-20

## 背景

任务 1.1 和 1.2 定义了文件协议的公共类型和第一批文件 schema（`workspace.yaml`、`project.yaml`、Concept）。过程中遇到了一系列格式问题：ULID 的大小写、时间戳的精度和时区、没测过的维度怎么写、空的插件配置怎么写、Obsidian 的 `tags` 能不能写成单个字符串、遇到未知字段怎么办、错误信息怎么表达。这些问题需要一条统一的原则，以后遇到新的格式问题也按它判断。

## 决策

### 核心原则

**同一个值只有一种写法。** 以后遇到新的格式问题，先按这条原则判断。

由此得出的规则：

- **ULID 只认大写**。CLI 接收用户输入时可以先转成大写再校验，那是 CLI 的事，schema 不管。
- **时间只用 UTC**，格式固定为 `YYYY-MM-DDTHH:mm:ssZ`，不带毫秒，不带时区偏移。同一秒内的先后顺序靠 ULID 区分。
- **五个维度必须写全**，没测过写 `null`，不能省略。
- **空的插件配置写 `{}`**，不能写成 `null`。
- **`tags`、`aliases` 只接受列表**，不接受单个字符串。

### 相关规则

- **对象一律严格校验**：出现未知字段就报错。两个例外：
  - Concept 的 frontmatter：为了兼容 Obsidian，未知字段原样保留，并给出警告；
  - 插件配置对象：内容由插件自己的 schema 校验（4.3）。
- **结构化错误**：稳定的错误码 + 参数 + 按语言分的消息表，测试只断言错误码。目前只有英文消息表（2026-11-20 决定）。

### schema 的外部依赖（硬性规则）

- `schema` 的运行时代码**只允许依赖 `zod`**。新增任何外部依赖都必须先写 ADR。
- 生成 ULID 属于 Platform 端口的 `IdGenerator`（1.7），ULID 库应该放在那边的实现里。schema 只用正则校验 ULID 的格式。

## 理由

- 掌握度投影要逐字节确定（不变量 3）。
- 读后再写不能改变文件（1.9）。
- Git diff 里不能有格式噪音。
- 比较和排序都可以直接按字符串进行。
- ULID 只认大写还有一个原因：ULID 会出现在文件名里，而 macOS 和 Windows 的文件系统默认不区分大小写。
- 限制 schema 的外部依赖：
  - 所有包都依赖 schema，包括 `ui-*`（ADR-0012），它的每个依赖都会被带进所有包和所有平台的构建里，所以要保持最少；
  - schema 要在 Web Worker、Node CLI、Git merge driver 和以后的 Web 版本里原样运行，它的每个依赖都必须在所有这些环境里可用；
  - 依赖越少，供应链风险越低，升级时的版本冲突也越少。

## 考虑过的其他方案

- **宽松解析多种写法，写入时再统一**：读后再写会改变文件，而且解析规则会越来越复杂。
- **容忍未知字段来兼容新版本**：有 `schema_version` 加迁移（ADR-0005）这条路，不需要这样做；而且会放过拼写错误。
- **直接使用 zod 的错误码**：会随 zod 的版本变化（zod 3 升到 4 时就改过）。

## 后果

- 以上规则都已经在 `@mastery/schema` 里实现，并有测试覆盖（1.1、1.2）。
- dependency-cruiser 规则 `schema-runtime-only-zod` 检查 `packages/schema/src` 的运行时代码只 import `zod`（README 第 6 节硬性禁止第 6 条）。测试文件和测试工具（`*.test.ts`、`testing.ts`、`test-helpers.ts`）不受这条限制。
- 新的文件 schema（1.3、1.4、1.11 等）都要遵守这些规则。
