# ADR-0006 掌握度投影提交到 Git，冲突由 merge driver 重算解决

- **状态**：已定
- **日期**：2026-11-19（决策日期早于仓库创建，2026-11-20 补记）

## 背景

掌握度是根据证据和版本化的规则算出来的派生数据（README 第 2 节）。同一个 Workspace 可能在多台设备上同时产生新的证据，同步时会发生合并。

## 决策

- 掌握度投影 `mastery/<concept-slug>.yaml` 提交到 Git，历史 `mastery/history/<concept-slug>.jsonl` 只追加。
- Workspace 的 `.gitattributes` 写 `mastery/*.yaml merge=mastery-recompute`。发生合并冲突时，不做文本合并，而是根据合并后的全部证据重新计算投影。

## 理由

- 提交投影以后，用户不打开应用，看 Git 历史就能看到自己的进步。
- 投影 = fold(证据, 规则@版本)，是确定性的，所以冲突时可以根据合并后的全部证据重新计算，不需要文本合并。多设备冲突里最难的这一部分因此不存在了。

## 考虑过的其他方案

- **不提交投影**：Git 历史里看不到进度。
- **对投影做文本合并**：会合出错误的结果。
- **所有掌握度放在一个大文件里**：成为冲突热点。

## 后果

- 同一组证据加同一版本的规则，算出的投影必须逐字节相同，不依赖文件读取顺序和当前时间（不变量 3）。
- 投影只能由 Mastery Core 写出（不变量 4）；手工修改投影会被重算覆盖。
- merge driver 需要在不启动运行时的情况下调用 Core（见 ADR-0002）。
